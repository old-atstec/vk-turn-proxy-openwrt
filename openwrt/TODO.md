# Доработки (отложено)

## Несколько ссылок VK в анонимном режиме

`list vk_link` уже принимается в UCI, но анонимный режим ядра (`proxy.Config.VKLink`) чеканит
креды только с **первой** ссылки; остальные используются лишь в режиме входа по cookies
(`SetVKCookieAuth`). Ограничение VK — около 20 соединений на ссылку.

Что нужно, чтобы держать больше 20 соединений:
- пул кредов (`pkg/proxy/creds.go`, `credPool`) — слот знает свою ссылку; минт идёт по ссылке слота;
- распределение соединений по ссылкам (≤ 20 на ссылку), учёт этого в `poolSize`;
- `CallUnavailableError` одной ссылки не должен останавливать остальные;
- статус: по ссылке — активные соединения, ошибки.

Изменение в ядре заметное — делать отдельной задачей, с тестами пула.

## Капча из LuCI (фаза 2)

Сейчас при капче, которую не прошёл автосолвер, статус показывает флаг и ссылку, демон
повторяет попытки. Ручное решение через LuCI потребует локального HTTP-прокси страницы капчи:
только `127.0.0.1`, обязательный таймаут, без открытого `/generic_proxy` и `Access-Control-Allow-Origin: *`,
проверка `Host`, порт закрыт в fw4.

## Размер бинарника

~12,7 МБ (arm64, `-s -w`). Для роутеров с 16 МБ флеша — UPX не рекомендуется (wireguard-go);
вариант — урезать ядро от режимов WRAP / csqtt / legacy (сборочными тегами).
