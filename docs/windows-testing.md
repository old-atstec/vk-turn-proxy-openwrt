# Проверки Windows-приложения на настоящем ПК

Приложение собрано и проверено тестами на Mac; **на Windows оно ещё не запускалось**. Этот список —
первый прогон на ПК (Windows 10/11 x64). Что делает каждая часть — [windows/README.md](../windows/README.md).

Подготовка: `windows/build.sh` → `windows/out/vkturn-<ver>-windows-amd64.zip` на ПК. Для подключения
нужен пир на сервере: проще всего выдать подключение в панели `vkturn-panel` (ссылка `vkturn://`), или
вручную — «Новый ключ» в приложении и `wg set wg-turn peer <публичный> allowed-ips 10.66.66.<N>/32` на
VPS (после добавления пира — переподключить туннель: сессии, открытые до него, сервер считает зомби).
Ключ роутера не использовать — он занят.

Журналы: вкладка «Журнал» в окне; сервис — «Просмотр событий → Журналы Windows → Система» (старт и
падения сервиса `VK TURN`).

## 1. Установка

1. Распаковать zip в «Загрузки», запустить `vkturn.exe` → один запрос UAC → открылось окно (Edge без
   адресной строки), в трее серый значок.
2. Проверить: `C:\Program Files\VK TURN\` — три файла; `sc qc VKTurn` — `AUTO_START`,
   `"C:\Program Files\VK TURN\vkturn.exe" service`; `services.msc` — «VK TURN» работает от
   «Локальная система».
3. ACL: `icacls "%ProgramData%\VK TURN"` — только `NT AUTHORITY\SYSTEM` и `BUILTIN\Администраторы`
   (без наследования); `icacls "%ProgramData%\VK TURN\ui-token"` — плюс ваш пользователь `(R)`.
4. Меню Пуск → «VK TURN» открывает окно; второй запуск не создаёт второй значок в трее.
5. `vkturn://` и `.vkturn`: открыть ссылку из панели (или файл двойным щелчком) — окно с
   предпросмотром импорта.

## 2. Подключение «по доменам» (по умолчанию)

1. Импортировать подключение → «Импортировать и подключить». Ожидаемо: «Подключение к релеям VK…» →
   «Рукопожатие WireGuard…» → «Подключено», значок зелёный. В журнале: `proxy: first connection up`,
   `app: the adapter N: 10.66.66.x/24, mtu 1280, K route(s)`, `DNS: every lookup through 127.0.0.1:53`.
2. Списки: на «Настройки» у списка category-ai — число имён и время загрузки, без ошибки.
3. Адаптер: `ipconfig` — «vkturn» с 10.66.66.x; `route print -4` — `1.1.1.1/32` через него, **нет**
   `0.0.0.0/1`.
4. NRPT: `Get-DnsClientNrptPolicy` (PowerShell) — правило для `.` с сервером `127.0.0.1`.
5. Имя из списка: `Resolve-DnsName chatgpt.com -Type A` → адреса; `route print -4` — у каждого маршрут
   /32 через vkturn; `Resolve-DnsName chatgpt.com -Type AAAA` — пусто. Сайт из списка открывается,
   и внешний IP на нём (или на https://ifconfig.co, если добавить его в «Свои домены») — сервера.
6. Имя не из списка: `Resolve-DnsName example.com` — ответ есть, маршрута /32 нет; внешний IP на
   обычном сайте — провайдера.
7. Счётчики на главной: «DNS через туннель N из M», «Маршруты K + n по именам» растут.
8. Firefox: `use-application-dns.net` → NXDOMAIN (`Resolve-DnsName use-application-dns.net`).
9. Chrome/Edge с «Безопасный DNS → текущий поставщик»: сайт из списка идёт через туннель. С явным
   поставщиком (Cloudflare) — ожидаемо мимо (задокументировано): проверить и записать.

## 3. «Весь трафик» и «По подсетям»

1. Переключить на «Весь трафик» (туннель перезапускается): `route print` — набор маршрутов без
   локальных сетей, плюс `::/1` и `8000::/1`; внешний IP любого сайта — сервера; веб-морда роутера
   192.168.x.1 открывается (локальные сети мимо). `ping -6 2001:4860:4860::8888` — не проходит
   (IPv6 не утекает).
2. Петли нет: туннель живёт дольше 5 минут, `conns_active` не падает (сокеты демона привязаны к
   физическому интерфейсу через `IP_UNICAST_IF`).
3. «По подсетям» с одной подсетью: маршрут только её, NRPT-правила нет (`Get-DnsClientNrptPolicy`
   пуст).

## 4. Сеть меняется

1. Wi-Fi ↔ кабель (или выключить/включить адаптер): в журнале `app: the network is now …`,
   туннель восстанавливается без перезапуска.
2. Сон/пробуждение ноутбука: туннель возвращается сам (возможно, через «Нет связи» до минуты).
3. Выдернуть сеть совсем: «Нет связи»; вернуть — подключено.

## 5. Остановка, сбои, перезагрузка

1. «Выключить»: в журнале `app: stdin closed — stopping`, `stopped`; адаптера vkturn нет в
   `ipconfig`; `Get-DnsClientNrptPolicy` пуст; DNS работает (`Resolve-DnsName example.com`).
2. Сбой сервиса: при включённом туннеле `taskkill /f /im vkturn.exe` (от администратора, убивает и
   сервис) → демон умирает с ним (job object), Windows перезапускает сервис через ~3 с, он удаляет
   NRPT; DNS работает.
3. «Подключаться при запуске Windows» → перезагрузка: туннель поднимается до входа; после входа
   значок в трее.
4. Обновление: собрать новую версию, запустить `vkturn.exe` из нового архива → UAC → сервис
   перезапущен на новой сборке, настройки сохранены.
5. Удаление: `"C:\Program Files\VK TURN\vkturn.exe" uninstall` → сервис, ярлык, обработчики
   `vkturn://` удалены; по ответу — и `%ProgramData%\VK TURN`; папка Program Files исчезает через пару
   секунд.

## 6. Скорость

Сравнить с роутером при тех же `conns` (замеры роутера — [openwrt/TODO.md](../openwrt/TODO.md);
в эмуляторе Android: вниз 10–16, вверх ~23 Мбит/с на 20 соединениях).

## Известные риски первого запуска

- Правило NRPT с сервером `127.0.0.1` — так делает OpenVPN, но на конкретной сборке Windows не
  проверено. Если имена из списков не получают маршрутов, а журнал без ошибок — проверить
  `Get-DnsClientNrptPolicy` и `Resolve-DnsName chatgpt.com -Server 127.0.0.1`.
- Порт 53 на 127.0.0.1 может быть занят (локальный DNS-прокси, Acrylic) — окно скажет об этом.
- Трей и `CreateIconFromResourceEx` с PNG — проверить, что значок виден и меняет цвет.
- `status.json` демон переименовывает поверх старого, а сервис читает его раз в секунду: если
  Windows откажет в замене открытого файла, в журнале изредка будет `status: … Access is denied` —
  безвредно (следующая запись через 5 с), но стоит отметить, как часто.
- Права `SERVICE_PAUSE_CONTINUE` на Dnscache у SYSTEM (перечитать NRPT без перезапуска клиента DNS):
  если в журнале `DNS policy: Access is denied` — правило применится не сразу.
