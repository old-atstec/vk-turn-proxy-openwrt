# Устройство и решения

Почему сделано так, а не иначе. Пользовательская сторона — [openwrt/README.md](../openwrt/README.md).

## Задача

Туннель WireGuard через TURN-релеи звонков VK — ещё один выход роутера, который NetShift
(sing-box) назначает спискам доменов и подсетей, как обычный WireGuard/AmneziaWG-интерфейс.
Транспорт — родной режим iOS-приложения anton48 **SRTP** (DTLS-SRTP поверх TURN, креды через путь
VK Звонков без капчи): на тестах 2026-10 он быстрее альтернатив (~30 Мбит/с против единиц у DTLS) и
не требует капчи. Десктопный клиент апстрима сам создавал tun, менял маршруты и DNS и вёл журнал
отката; на роутере всё это — работа netifd, UCI, procd, ubus и LuCI.

## Разделение обязанностей

```
UCI network.<iface> (proto vkturn)
  └─ netifd → /lib/netifd/proto/vkturn.sh setup
       ├─ пишет /var/run/vkturn/<iface>/config (0600, каталог 0700): ключи, ссылка, опции
       ├─ vk-turn-proxyd -config … -check (ошибки → proto_notify_error + block_restart)
       └─ proto_run_command vk-turn-proxyd -config …
            ├─ tun <iface> (wireguard-go/tun), IFF_UP ioctl-ом, без адреса
            ├─ pkg/proxy: пул кредов, TURN-сессии, DTLS-SRTP к серверу
            ├─ wireguard-go device поверх turnbind (bind = прокси)
            ├─ status.json раз в 5 с и на переходах
            └─ /lib/netifd/vkturn-notify.sh up|down
                 up:   proto_init_update <dev> 1, адреса из UCI (+ 0.0.0.0/0, только если defaultroute 1)
                 down: proto_init_update <dev> 0       — как ppp-up / ppp-down
```

### Решения (раздел 8 ТЗ)

1. **Адреса и маршруты ставит netifd, а не демон.** Демон не вызывает `ip` и не держит своих
   маршрутов, нечего откатывать; netifd сам применяет `metric`, `ip4table`, `defaultroute`;
   `ip-full` не нужен. Хук вызывается после первого handshake — пока туннель не несёт трафик,
   интерфейс не `up`.
2. **Статус — файл + ucode-плагин rpcd**, а не ubus-объект из Go: rpcd уже исполняет ucode-плагины,
   ubus-клиент без cgo — лишний код в демоне. `reconnect` — сигнал `SIGUSR1` (плагин проверяет, что
   pid принадлежит демону этого интерфейса, по `/proc/<pid>/cmdline`).
3. **fwmark / bind-device на всех сокетах прокси** (`pkg/proxy/sockopt.go`), по умолчанию выключены.
   NetShift метит и **локальный** трафик роутера к fakeip и своим подсетям (`mangle_output`);
   `0x200000` — метка исходящих sing-box, которую NetShift пропускает. Пинов `/32` (как у десктопного
   клиента) нет вовсе: на роутере маршрут по умолчанию и так WAN.
4. **NetShift `vpn`-секция**: outbound `{type: direct, bind_interface: <iface>}` строится без ручных
   правок; `interface` — имя устройства, поэтому tun называется как UCI-интерфейс. Когда интерфейс
   down, соединения к доменам секции падают, мимо туннеля не утекают; sing-box не падает.
5. **Кэш кредов на флеше** (`/etc/vkturn/<iface>/creds.json`, 0600 в 0700) — решение владельца;
   tmpfs — опцией `cred_cache`.
6. **Одна ссылка VK** в анонимном режиме (ядро чеканит с первой); `list vk_link` уже в UCI.
   Соединения расходятся по всем релеям, которые VK отдаёт для звонка (`spread_relays`, по
   умолчанию включено; в приложении — только первый). Скорости это не прибавило: скорость задаёт
   число соединений (~2 Мбит/с на каждое, пейсер сервера под лимит VK), замеры — в TODO.
   Расширение на несколько ссылок — [openwrt/TODO.md](../openwrt/TODO.md).
7. **Свой форк**: iOS-приложение, его Go-мост и десктопный клиент удалены (с ними ушёл журнал отката,
   исполнявшийся от root из текущего каталога — риск 6.1 ТЗ).

## Жизненный цикл туннеля

**Живой** туннель = есть TURN-сессия **и** handshake WireGuard моложе 160 с (`handshakeStale`).
Keepalive (25 с) заставляет WireGuard перехэндшейкиваться при первой отправке после 120 с, то есть на
простаивающем туннеле — через 120–145 с; 140 с оказалось мало (замер: максимум 125 с за 6 минут
простоя, но теоретически до ~145). Только счётчика сессий мало: при полном дропе трафика сессии
ядра умирают по одной, минутами (замер: 20 → 4 за 150 с).

- Не живой дольше `down_after` (60 с) → хук `down`; ожил → сразу `up`.
- Сессии есть, а handshake старше 160 с → сервер потерял их (рестарт сервера теряет SRTP-сессии,
  релеи держат клиентские) → `ForceReconnect`, не чаще раза в 3 мин (`kickEvery`).
- Смена WAN (новый шлюз, интерфейс или адрес по `/proc/net/route`) → `OnPathChange`/`OnPathUp`
  ядра по правилу десктопного клиента: одна смена сети — одно событие. Сон не детектируется
  (роутеры не спят, поздний тик под нагрузкой не должен дёргать проверку).

## Кэш кредов и перезапуски

Пул ядра загружает слот, использованный за последние 10 минут, как **pending**: релей может ещё
держать его аллокации (квота ~10 на личность и релей). Если pending все слоты, пул ничего не чеканит
и ждёт — замер: перезапуск через секунду после остановки простоял 10 минут на нуле. Поэтому демон
**удаляет кэш моложе 11 минут** при старте (`dropFreshCache`) и чеканит свежие личности (~1 с по
пути VK Звонков). Старый кэш используется — он экономит минт после долгого простоя, что важно,
если VK потребует капчу.

Смена ссылки в LuCI: рядом с кэшем хранится sha256 ссылки (`creds.json.link`); другая ссылка — кэш
выбрасывается.

Известное ограничение ядра: если релеи недоступны **при живом WAN** (обрыв пути без смены сети),
сессии не могут вернуть аллокации, их слоты помечаются VK-saturated на ~10 мин, и туннель живёт на
оставшихся. Запас — `pool_reserve` (по умолчанию 1, в приложении 3).

## Безопасность

- Приватный ключ: в UCI (как у `proto wireguard`), демону — файлом 0600, не в argv и не в окружении.
  Конфиг интерфейса netifd передаёт обработчику аргументом — так же, как для wireguard/amneziawg.
- Конфиг с правами шире 0600 демон не принимает; каталоги статуса и кэша — 0700, не симлинк, свои.
- В логах замаскированы токены VK, TURN-логин и пароль, токен сессии капчи (`redact.go`); в rpcd
  getPublicKey ключ идёт демону через stdin.
- Переменные `VK_*` (отладка ядра, одна из них пишет файл по указанному пути) сбрасываются при старте.
- Демон ничего не слушает. Ничего не пишет в CWD (тест), не вызывает программ, кроме хука netifd
  (тест-скан исходников).

## Логи

Строки демона netifd сам кладёт в syslog (`netifd: <iface> (<pid>): …`), поэтому без меток времени.
На уровне `info` отбрасываются периодические диагностики ядра, написанные для iOS (`reorder(`,
`ALLOC-SPIKE`, `memstats`, `pathstats`, рутинные `pion/turnc` про refresh, поканальная статистика):
без фильтра — ~900 строк за 7 минут, кольцевой буфер `logread` их не вмещает. `log_level debug` —
всё.
